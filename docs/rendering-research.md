# Rendering research and measured changes

2026-11-04 · Three.js 0.180 / WebGL2 preview · Blender/Cycles 4.3.2 export

Preserve source geometry, materials, camera framing, requested render samples and recovery behavior. Improve the image at the responsible layer; preview approximations do not establish parity with Cycles.

## Implemented locally

| Change | Mechanism and budget | Limits / implementation |
| --- | --- | --- |
| Sharper settled inspection | Keep motion/playback at 1280px longest edge, 921,600 pixels and at most one buffer pixel per CSS pixel. After 180ms without activity, allow 1920px, 2,073,600 pixels and at most 1.5 buffer pixels per CSS pixel, never exceeding device pixel ratio. One delayed redraw; no idle loop or asset reload. | Playback explicitly holds the motion budget. Hidden/offscreen/suspended views cancel promotion; data saving holds the smaller budget. Capture uses its existing separate resolution. [previewResolution.ts](../web/src/previewResolution.ts), [viewport.ts](../web/src/viewport.ts), [App.tsx](../web/src/App.tsx). |
| Antialiasing through image finishing / DOF | Use 2× MSAA only when both actual RGBA16F color and DEPTH_COMPONENT24 depth formats report support for two samples. Otherwise use zero; do not silently substitute four. Disable for data saving. | Restores geometry coverage antialiasing lost by the previously single-sample offscreen target. Adds GPU storage/bandwidth; does not solve specular shimmer or establish a frame-rate improvement. [previewAntialias.ts](../web/src/previewAntialias.ts), [DepthOfFieldPreview.ts](../web/src/DepthOfFieldPreview.ts). |
| Existing environment and area lighting | Retain roughness-filtered PMREM environment lighting and LTC rectangular-light shading. Reuse the live presentation camera, avoiding a separate cached glass-transmission target for every draw. | These are existing capabilities, not newly implemented research algorithms. Imported baked/unlit room textures remain baked/unlit. Area-light shadows are a separate approximation. [viewport.ts](../web/src/viewport.ts). |
| Reuse native render setup | Enable Cycles persistent data within the worker's bounded frame batch. Every frame still updates camera/object/light state. `GESSO_CYCLES_PERSISTENT_DATA=0` opts out. | Retains render data in memory; the batch process bounds its lifetime, not a universal RAM ceiling. Blender documents the speed/memory tradeoff under [Persistent Data, Performance](https://docs.blender.org/manual/en/4.4/render/cycles/render_settings/performance.html#final-render). The linked manual is 4.4; the local benchmark below uses the pinned 4.3.2 runtime. [blender_scene.py](../scripts/blender_scene.py), [jobs.py](../film/jobs.py). |
| Reuse verified static work | Resolve the scene's static support graph once per sampling operation. Cache only small world-asset verification facts while filesystem identity remains unchanged. | The verification LRU holds at most 128 records, each at most 4KiB serialized; it retains no full asset bytes, decoded buffers, scenes or failures. Lookups check file identity; changes require fresh validation. Each sampled frame retains independent mutable records. [scene.py](../film/scene.py), [worlds.py](../film/worlds.py). |

Local browser verification: at 842×660 CSS pixels, playback used an 842×660 drawing buffer; after pause it settled to 1263×990. Post-processing controls were visible in Film → Output, Auto balance enabled finishing successfully, and the inspected browser error list was empty. This is local interaction evidence, not device coverage or a measured GPU speedup.

Native validation also passed six Blender roundtrip tests, a graded PNG still, and an eight-frame graded Watch/Water MP4 at 320×180 / 16 samples. The movie used pinned Blender 4.3.2 and FFmpeg 7.1.5; probing confirmed eight H.264/yuv420p frames. All final artifact hashes matched, and the three PNG stills exactly copied approved frame bytes. Local FFmpeg codec checks also covered ProRes/PCM, H.264/AAC, JPEG and WebP. These are pipeline checks, not a completed full-resolution campaign render.

## Local measurements

| Test | Before → after | What it establishes |
| --- | --- | --- |
| Cycles CPU, Blender 4.3.2, 320×180, 16 samples; frames 1, 121, 241, 360 rendered in one process per mode | Persistent data off: 4.6562, 4.2821, 4.2148, 3.8167s. On: 2.8823, 2.1017, 2.0119, 1.9963s. Excluding the first frame, median per warm frame **4.2148 → 2.0119s**. | All four decoded RGB images matched exactly between modes. This tiny four-frame test measures setup reuse; it is **not a completed 1080p film benchmark** or a predicted production speedup. |
| 360-frame fixture scene sampling; median of seven runs | **91.41 → 16.78ms** | Static graph reuse reduces local sampling work. This excludes GPU drawing, network transfer, Cycles and encoding. |
| Verification of unchanged 92MiB Water world asset | Repeated hash/content work about **95–125ms → 0.12ms** on a warm metadata-cache hit | Avoids rereading immutable bytes after a verified load. A cold load or changed file still performs full verification. This is not a faster download or mesh decode. |

## Research and next decisions

Publication types below are explicit: a SIGGRAPH course presentation is not a peer-reviewed SIGGRAPH paper. Fits and implementation recommendations are project judgments, not performance claims from the sources.

| Technique / primary source | Publication | Fit and decision |
| --- | --- | --- |
| [Real Shading in Unreal Engine 4](https://cdn2.unrealengine.com/Resources/files/2013SiggraphPresentationsNotes-26915738.pdf) — Brian Karis, 2013 | SIGGRAPH *Physically Based Shading in Theory and Practice* course notes. [Course syllabus](https://blog.selfshadow.com/publications/s2013-shading-course/). | **Next recommendation:** cache one product-excluded local room reflection probe, then prefilter it with existing PMREM. A proposed 256px cube captures six faces / 393,216 source pixels, plus filtering, only when world/probe inputs change. Do not rebuild on camera movement or grading. A single probe has parallax errors; baked LDR color cannot recover missing HDR radiance. |
| [Real-Time Polygonal-Light Shading with Linearly Transformed Cosines](https://eheitzresearch.wordpress.com/415-2/) — Eric Heitz, Jonathan Dupuy, Stephen Hill, David Neubelt, 2016 | Peer-reviewed ACM Transactions on Graphics / SIGGRAPH 2016 paper. | **Existing:** retain broad rectangular emitters for readable metal/glass highlights. LTC approximates BRDF integration efficiently; it does not supply occlusion. [Three r180 RectAreaLight](https://github.com/mrdoob/three.js/blob/r180/src/lights/RectAreaLight.js) explicitly lacks shadow support. |
| [High Quality Temporal Supersampling](https://de45xmedrsdbp.cloudfront.net/Resources/files/TemporalAA_small-59732822.pdf) — Brian Karis, 2014 | SIGGRAPH *Advances in Real-Time Rendering* course talk. [Course page](https://www.realtimerendering.com/advances/s2014/index.html). | **Later:** moving-film temporal stability requires reprojection, history rejection and treatment of cuts, disocclusions, moving parts, glass and Gaussian content. [Three r180 TAARenderPass](https://github.com/mrdoob/three.js/blob/r180/examples/jsm/postprocessing/TAARenderPass.js) is static jitter accumulation **without reprojection**. Finite idle accumulation is possible but adds repeated scene draws; it is not moving TAA or a drop-in speed improvement. |
| [Practical Realtime Strategies for Accurate Indirect Occlusion](https://www.activision.com/cdn/research/PracticalRealtimeStrategiesTRfinal.pdf) — Jorge Jimenez, Xian-Chun Wu, Angelo Pesce, Adrian Jarabo, 2016 | Activision Technical Memo ATVI-TR-16-01 and [SIGGRAPH course presentation](https://blog.selfshadow.com/publications/s2016-shading-course/). | **Later:** selective GTAO for product contact/creases, with a measured radius and restricted contribution. Whole-image multiplication would darken baked room lighting again. Screen-space depth misses hidden occluders; [r180 GTAOPass](https://github.com/mrdoob/three.js/blob/r180/examples/jsm/postprocessing/GTAOPass.js) adds geometry-buffer, AO and denoising work. Its published console timing does not predict our browser cost. |
| [Efficient GPU Screen-Space Ray Tracing](https://jcgt.org/published/0003/04/04/) — Morgan McGuire, Michael Mara, 2014 | Peer-reviewed *Journal of Computer Graphics Techniques* 3(4), 73–85; not SIGGRAPH. | **Later:** selective SSR could supplement a visible reflective floor with a probe fallback. It cannot recover offscreen/hidden geometry and needs depth/normal/reflection buffers. Do not promise product reflections in generated static water or use SSR as the sole metal/glass reflection source. |
| [Spatiotemporal Reservoir Resampling for Real-Time Ray Tracing with Dynamic Direct Lighting](https://research.nvidia.com/publication/2020-07_spatiotemporal-reservoir-resampling-real-time-ray-tracing-dynamic-direct) — Benedikt Bitterli, Chris Wyman, Matt Pharr, Peter Shirley, Aaron Lefohn, Wojciech Jarosz, 2020 | Peer-reviewed ACM Transactions on Graphics / SIGGRAPH 2020 paper. | **Research direction:** ReSTIR reuses stochastic lighting samples across space/time. Our WebGL2 raster preview lacks the required ray-visibility/reservoir pipeline; Cycles 4.3.2 does not gain this algorithm from an application setting. Adopting it would require renderer work and new validation, not another post-processing pass. |

The next useful comparison is the cached room probe against the current environment lighting, with product material/camera/exposure fixed. Defer full moving TAA, GTAO and SSR until their specific artifact and GPU cost are measured.
